# Test Vectors

These files are generated by `python -m model.gen_vectors`, so don't edit them by hand.

Every `.mem` file has a `//` header that gives the bit slice of each field. Each data line is one hex word, which a testbench loads into an array of wide registers:

```verilog
reg [67:0] vec [0:17487];
initial $readmemh("bch_dec.mem", vec);
// received = vec[i][66:52]; s1 = vec[i][51:48]; ... ok = vec[i][0];
```

| File | Lines | Word | Contents |
|------|-------|------|----------|
| `gf_mul.mem` | 256 | 12 bit | a, b, a·b. Exhaustive |
| `gf_inv.mem` | 16 | 8 bit | a, a⁻¹ (inv(0) = 0). Exhaustive |
| `bch_enc.mem` | 128 | 24 bit | message, codeword. Exhaustive |
| `bch_dec.mem` | 17488 | 68 bit | received, S1, S3, Λ1, Λ2, error mask, corrected, ok. All errors of weight ≤ 2 on every codeword, plus 2000 weight-3 patterns |
| `fe_r1.mem`, `fe_r3.mem`, `fe_r5.mem` | 24 each | 732 bit | Full enrolment and reconstruction: w, messages, helper, KCV, w′, key, key_valid, challenge, tag |
| `siphash.mem` | 278 | 712 bit | key, message length, message (up to 64 bytes, zero padded), tag. 64 reference vectors, 200 random cases, 14 KDF/KCV/MAC messages exactly as the design uses them |
| `espresso/gf_mul.pla`, `espresso/gf_inv.pla` | | | Full truth tables (`.type fr`) as ESPRESSO input |

The `.mem` files from Python have no Verilog `$readmemh` path set. Copy them next to the simulation, or use an absolute path in the testbench.
